01 — Chrome extension

Restyle any website, one element at a time.

Pick any element, describe the change in plain words, and see it restyled live. The change is saved per site.

22/22end-to-end checks pass
MV3Manifest V3 extension
Per-sitestyles saved and reapplied on load

Problem

Sites look the way their owners want, not the way I want. Custom CSS is slow and breaks whenever the markup changes.

What I learned

Never let the model write code. Graft only accepts a whitelisted set of scoped CSS and a few allowed DOM operations, and everything else is sanitized. That's what makes it safe to run on any site. Host pages also fight your UI: even inside a Shadow DOM, site CSS overrode my panel, so I switched to explicit styles and a solid background. And every LLM call needs a timeout and an error message a person can read.

What I learned

Page metadata lies. For the same text it pointed to a page from 2024, while the Wayback Machine showed the source was 26 years older. Independent evidence beats what a page says about itself.

03 — ML · Active learning

Label less, learn the same.

Two identical classifiers start from the same 10 labels. One gets random images, and the other asks for the ones it's least sure about.

80labels to reach 90%
150labels picked at random
0dependencies, all in the browser

Problem

Labeling is the expensive part of ML. I cut it by 90% at work with active learning, and I wanted to show the mechanism live.

What I learned

Uncertainty sampling isn't a free win. With only 10 labels the model's own uncertainty is unreliable, and entropy sampling lost to random on one seed. Testing several seeds made margin sampling the default. My first full-label baseline was also undertrained, which made active learning look better than it was. Training it to convergence fixed the comparison.

04 — CV · On-device

Cut out the subject. Nothing uploaded.

Drop a photo and a 44 MB segmentation network removes the background in your browser, then you swap it.

2.6–4.2 sper photo on the device
44 MBint8 model, open weights
0uploads

Problem

Most background removers upload your photo to someone's server. I wanted one that does it all in the browser.

What I learned

Serving headers mattered more than the model. Without cross-origin isolation, WASM runs on a single thread, and two response headers made it 3× faster. Some failures were also silent, like local models being disabled by default and a wrong input name. Capturing page errors in the test harness was the only way to find them.

05 — ML · Federated learning

Train together, share only weights.

Eight clients keep private data and train one model with FedAvg. A slider adds label skew so you can watch non-IID data hurt.

8clients
90.8%FedAvg under heavy skew
97.6%with all data in one place

Problem

Sensitive data, like medical records, can't be pooled in one place. Federated learning trains on it anyway, but it's hard to picture what that costs.

What I learned

Federated learning protects privacy, not bandwidth. On a small dataset the weights sent around were 55× bigger than the data itself. And uneven data is the real story: averaging still builds a decent model from clients that are only 33% accurate on their own, but it trails centralized training by about 7 points.

06 — LLM · Evaluation

Unit tests for LLM answers.

Write claims as assert lines and each one is checked against your source. The output reads like pytest: PASS, FAIL or SKIP.

9/10claims right on held-out tests
~1 sper run
0API keys or servers

Problem

LLMs state wrong facts with confidence. I wanted to check answers against a source the way I test code.

What I learned

Pronouns break sentence-level checking. "It was first released in 1991" didn't support "Python was first released in 1991" until each piece of evidence included the sentence before it, and that one change fixed two wrong verdicts. A naive sentence splitter also cut "Python 3.0" in half.
