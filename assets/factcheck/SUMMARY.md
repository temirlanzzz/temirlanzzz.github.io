# pytest-facts: unit tests for LLM answers

**Pitch:** paste a source of truth and the claims an LLM made, written as `assert "claim"` lines. Each claim retrieves its closest evidence sentences, and an NLI model marks it PASS (entailed), FAIL (contradicted) or SKIP (the source is silent). The output looks like pytest.

**Stack:** static HTML/JS, transformers.js v3, with `all-MiniLM-L6-v2` for retrieval (top-3 by cosine) and `cross-encoder nli-deberta-v3-xsmall` (int8 ONNX) for entailment. Both are vendored locally (115 MB), so there are no API keys and no server.

**Measured** (headless Chromium, 8-core box):
- Model load: **3.2–3.4 s** from local files. A full 8-claim test run takes **1.05–1.14 s**, and 10 claims take 1.5 s.
- Built-in sample (8 claims, 3 true, 4 false, 1 unsupported): **8/8** verdicts match the intended labels. I wrote this sample and fixed the pipeline against it, so treat it as a tuning set.
- Held-out check (10 new claims written after the fix): **9/10** correct. The miss was "Guido van Rossum worked at Google", marked FAIL instead of SKIP, which is an overconfident contradiction on an unsupported claim.

**Lessons**
- Pronouns break sentence-level NLI. "It was first released in 1991" did not entail "Python was first released in 1991" until each premise included the sentence before it. That one change flipped two wrong verdicts.
- A naive regex sentence splitter cut "Python 3.0" into two pieces. Splitting on punctuation followed by a capital letter fixed the evidence.

**Limits:** a small NLI model on short, clean sources. It does not handle numbers or dates by reasoning, only by NLI pattern, and it will sometimes call an unsupported claim false. The sample "LLM answer" is hand-written, not generated by an LLM.
